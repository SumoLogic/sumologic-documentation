This content release includes:
- 2 new Match rules that give visibility into generative AI risk
- A new rule that detects AI model files downloaded from public repositories. It triggers when a network request names an AI model file extension (`.pkl`, `.pt`, `.pth`, `.bin`, `.gguf`, `.safetensors`, `.ckpt`, `.joblib`, `.onnx`, `.h5`) on a known model repository host, fetches a content-addressed object from a model repository content delivery network, or pulls from a model registry or download endpoint. Models pulled from public repositories can carry executable payloads, and attackers have published weaponized models and typosquatted names to reach organizations that adopt them. Add approved model sources to the `allowed_ai_domains` match list to exclude them
- A new rule that detects sensitive data sent to Generative AI (GenAI) tools. It triggers when a single record contains both a Data Loss Prevention (DLP) finding and a write request (POST, PUT, PATCH, upload, or edit) to a GenAI destination, identified by domain list or Cloud Access Security Broker category. Employees or automated integrations may expose personal data, credentials, or source code outside the organization's control, and many GenAI providers may retain or use submitted input for model training. Add approved GenAI domains to the `allowed_ai_domains` match list to exclude them
- Expanded CrowdStrike Falcon visibility with a new correlation rule detection summary mapper and an update to the existing one
- Updated Microsoft Azure JSON parsing to support an additional timestamp format
