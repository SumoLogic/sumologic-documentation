Sumo Logic will enforce correct syntax for boolean expressions in log search queries. Previously, Sumo Logic accepted queries with incomplete AND/OR syntax, such as:

```
| where user_username = "root" and success
| where ip matches "192.*" or "1.*"
```

In the above examples, `success` and `1.*` aren't valid boolean expressions on their own. These queries may not be returning the results you expect.

Starting **September 30, 2026**, this validation applies when you create or update a query, monitor, scheduled search, scheduled view, or dashboard panel. Saving one that uses this shorthand returns a validation error so you can complete it, instead of running with misleading results.

:::note
Existing saved content keeps running as-is. It only errors the next time you edit and save it. Review whether this change affects your operations, and whether you need to re-run any existing saved content. We still recommend proactively updating any queries, monitors, scheduled searches, or dashboard panels that use this shorthand to the explicit form.
:::

To fix affected queries, ensure each operand in an AND/OR expression is a complete boolean expression. For example:

```
| where user_username = "root" and success = true
| where ip matches "192.*" or ip matches "1.*"
```
