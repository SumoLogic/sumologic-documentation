We've modernized the Search Job API to be fully OpenAPI-compliant, stateless, and built for multi-tenant and AI-driven automation. By removing session cookie dependencies and adding parent-child org support, you can run faster, more reliable search jobs across complex environments and AI frameworks with zero cookie management overhead.

### What's new

- **OpenAPI compliance**. A standardized schema lets you auto-generate SDKs in any language and integrate natively with Postman and CI/CD pipelines.
- **Stateless architecture**. Session cookie dependencies are fully removed, eliminating 404 errors and unexpected job cancellations during scripting and automation.
- **AI and MCP readiness**. AI agents and Model Context Protocol (MCP) frameworks can now natively execute and poll long-running search jobs without hitting session timeouts.
- **Optimized execution defaults**. `requiresRawMessages` now defaults to `false`, speeding up query execution and reducing data transfer size.
- **Parent-child org support (MSSP)**. MSSPs and enterprise admins can now automate parent-child, cross-org searches via the API, previously only available through the UI.

For more information, see [Search Job API](/docs/api/search-job/).
